# Classic Comprehensive Documentation Profile

## 適用場景

完整仿造 CodeWiki 原始 LLM 文檔生成設計。核心原則：全面覆蓋、圖文並茂、模組間交叉引用取代重複說明。適合想要最完整記錄 codebase 的場合，無讀者類型限制——開發者、維護者、新進人員皆適用。

## TOC 組織邏輯

直接映射模組樹結構：
- 一個頂層「系統概覽」章節排在 `sections` 陣列**第一位**（讀者進入文檔的第一頁）
- 每個模組對應一個章節；有子模組的模組同時設定 `file` 與 `children`，父節點排在子節點**前面**
- 彙整型章節（純目錄節點）同樣排在其所有子節點前面

> **生成順序與顯示順序分開處理**：`doc_spec.json` 的 `sections` 陣列順序決定 HTML 導覽順序，生成批次由拓撲排序（`source_sections` 依賴）決定——兩者互不影響。系統概覽雖然顯示在最前，因為它的 `source_sections` 指向所有葉節點，實際上會在最後一批才生成。

略過：純測試模組、自動生成的程式碼、vendor 目錄。

## 各章節寫作指引

---

### 系統概覽章節

從所有已生成的模組文檔提煉全局視角（`source_sections` 指向全部葉節點）。不重複子節點細節，只做架構層面的彙整。

骨架（H2 標題固定，順序不能改）：

```
## 系統定位
{3-5 句說明系統整體目標、核心職責、解決的問題}

## 端對端架構圖
{mermaid graph LR 或 graph TD，顯示所有主要模組、依賴方向、以及系統邊界（外部輸入 / 輸出）；節點標籤使用模組名稱，連線標籤說明依賴類型（呼叫、資料、繼承等）}

## 核心模組索引
{每個模組一行：名稱 — 一句職責說明 — [→ 文檔連結]}

## 技術棧
{條列：語言、框架、資料庫、主要外部依賴，每項附一句說明其用途}

## 關鍵流程
{選出 1-3 個最重要的端對端業務流程，每個流程一個 mermaid sequenceDiagram 或 flowchart，搭配 2-3 句說明}
```

---

### 模組章節（葉節點，直接對應 source_modules）

目標：讓讀者不需要讀原始碼就能完全理解這個模組。語氣技術性、精確，有疑問時側重「為什麼這樣設計」而非只描述「做了什麼」。

骨架（H2 標題固定，順序不能改）：

```
## 模組簡介
{2-3 句說明此模組的職責與在系統中扮演的角色；說明它解決什麼問題、不做什麼}

## 架構與組件
{說明此模組內部的組件構成：class、function 群組、或子層次結構。

附 mermaid graph（graph LR 或 graph TD）：
- 節點 = 此模組內部的核心 class / 主要 function 群 / 子模組
- 連線 = 呼叫關係、繼承關係、資料傳遞方向
- 若有外部依賴（import 其他模組）也納入圖中，以虛線區分}

## 資料流程
{描述資料如何進入、在模組內被處理、再流出。

附 mermaid flowchart TD 或 sequenceDiagram：
- flowchart 適合單一模組內的處理流程
- sequenceDiagram 適合多個組件之間有明確呼叫順序的情境
若此模組沒有明顯的資料流（例如純工具函數集合），改以文字說明主要的計算或轉換邏輯}

## 公開介面
{表格列出所有對外暴露的 API、class、function：

| 名稱 | 類型 | 簽名 / 參數 | 說明 |
|------|------|------------|------|

若有重要的回傳型別、例外情形、副作用，在表格下方補充說明}

## 使用範例
{至少一個完整可執行範例，含 import 語句與預期輸出或行為說明。
若有多個典型使用情境，每個情境各一個範例，以 H3 小標題區分}

## 依賴關係
{兩個方向都要說明：

**此模組依賴**：條列它 import / 呼叫的模組，每個附對應文檔的內部連結，說明為何依賴（用什麼功能）

**被以下模組使用**：從 module_map.md 掃描反向依賴，條列所有使用此模組的上游模組，每個附對應文檔的內部連結；若無則寫「（此模組無被其他模組直接使用）」}
```

---

### 模組群組章節（有 children，同時有 source_modules）

此節點本身有程式碼，同時包含子模組。任務：說明此層的整體設計，不重複子模組細節（子模組文檔已覆蓋），但要清楚呈現群組的邊界與協作方式。

骨架（H2 標題固定，順序不能改）：

```
## 群組職責
{3-5 句：這個模組群組整體負責什麼、為什麼這樣切分邊界}

## 群組架構圖
{mermaid graph：顯示此層自身的組件 + 所有直接子模組 + 彼此的依賴關係；子模組節點連結對應文檔}

## 子模組說明
{每個子模組一段：
**[子模組名稱](對應文檔連結)**：一句說明其職責，以及與其他子模組的關係}

## 此層的公開介面
{若此層自身有公開 API，列出表格，格式同「模組章節」；若無則省略此 H2}

## 關鍵互動流程
{1-2 個最重要的跨子模組流程，附 mermaid sequenceDiagram 說明呼叫順序；若無明顯跨子模組流程可省略此 H2}
```

---

### 彙整型章節（有 children，無 source_modules）

純目錄節點，自身無程式碼。任務：說明這組章節的共同主題，引導讀者了解各子節點的關係與閱讀順序。

骨架（H2 標題固定，順序不能改）：

```
## 本章概覽
{2-3 句：說明這組章節在整體系統中的定位，以及它們共同覆蓋的關注點}

## 各章節說明
{每個子章節一段：[標題](連結) — 核心職責，以及與同層其他章節的關係；建議閱讀順序}

## 整體關係圖
{mermaid graph：顯示本群組下所有子章節之間的依賴或協作關係；若子章節間無明顯關係可省略此 H2}
```
